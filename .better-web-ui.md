## Design Context

### Users
People checking a QR code or unfamiliar link before opening it, often on a mobile device and sometimes while being asked to act quickly. They need to understand the destination and the limits of the risk result without needing security expertise. Secondary users include people reviewing local scan history and learners practising fraud recognition.

### Brand Personality
ClearScan is calm, precise, protective, and plain-spoken. It should help people pause and make an informed decision without using alarmist copy or implying that a low-risk result is a guarantee.

### Aesthetic Direction
Use the approved Editorial & Product-Focused direction: warm ivory surfaces, charcoal typography, a restrained terracotta accent, elegant serif display headings paired with Geist sans-serif body text, and structured layouts with fine separators. The interface should feel like a considered consumer security product. Keep security results, forms, history, learning, and navigation direct and legible. Avoid importing features, numbers, or claims from visual references.

### Implementation Defaults
- Existing stack: React 19, TypeScript, Vite 8, Tailwind CSS v4, Geist Variable, and Lucide React.
- Preserve the existing custom React state, scan service, localStorage hook, and Spring Boot API integration.
- Use existing HTML form controls and components; do not add a form or table dependency for this redesign.
- `components.json` configures the Base UI flavor of shadcn, but the application is primarily custom Tailwind UI.
- Existing stack and data flow take precedence over framework defaults.

### Design Principles
1. Make scanning a QR code or checking a URL the obvious first action on every relevant screen.
2. Explain risk classifications in plain language and keep the no-guarantee disclosure close to results.
3. Establish editorial hierarchy with serif display headings, clean sans-serif body text, spacing, and alignment before decoration.
4. Use semantic colors consistently, with text and labels in addition to color for risk meaning.
5. Use ivory, charcoal, and terracotta consistently; design mobile-first, keep navigation and forms usable by touch and keyboard, and respect reduced-motion preferences.
